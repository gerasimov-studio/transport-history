# Домен: модерация

## Ответственность

Очередь присланных changeset, проверка различий, пространственные области
ответственности, решение о публикации или возврате и аудит решения.

## Основные владельцы кода

- moderation-часть `services/backend/internal/api/workflows.go`
- общие account/workflow UI пока находятся в `src/features/account/`
- будущий отдельный frontend feature должен жить в `src/features/moderation/`

## Ключевые инварианты

- Полномочия задаются способностями пользователя и пространственной областью,
  а не отдельным типом кабинета.
- Один человек может параллельно иметь несколько ролей и собственные сценарии.
- Модератор видит и рассматривает только доступные ему области; superuser может
  управлять всеми областями и назначениями.
- Публикация changeset атомарно обновляет канонический журнал и проекцию либо не
  меняет их вовсе.
- Каждое решение хранит автора, время, исходный changeset и комментарий/причину.
- Проверка должна опираться на diff, а не только на итоговую геометрию.

## Граница с редактором и админкой

Editor отвечает за содержание присланного изменения. Moderation — за решение.
Administration назначает роли и области, но не подменяет review workflow.
